## ADDED Requirements

### Requirement: Интерактивные демонстрации

Витрина MUST предоставлять 14 сценариев с согласованными возможностями. Действия в демо выполняются на тестовых данных. GitHub использует открытые запросы к публичным репозиториям.

#### Scenario: 01. Студийная заявка

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Посетитель выбирает квартиру или дом, вводит площадь в м², бюджет в ₽, имя и телефон, проверяет сводку, может вернуться к значениям и отправляет заявку.

#### Scenario: 02. Объекты подрядчика

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Посетитель видит четыре объекта, фильтрует строительство, реконструкцию и отделку, открывает карточку с площадью, работами, фото с навигацией и этапами.

#### Scenario: 03. Каталог и корзина

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Покупатель ищет товары, сортирует по цене, меняет количество и видит сводку заказа.

#### Scenario: 04. Консультация

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Клиент проходит ветку по услуге, отвечает на уточнения, менеджер получает карточку с перепиской.

#### Scenario: 05. Расписание

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Клиент выбирает услугу и день, видит свободные окна с учётом длительности и может перенести запись.

#### Scenario: 06. Продажа

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Клиент собирает корзину, выставляет счёт, оплачивает тестовым способом или повторяет после ошибки.

#### Scenario: 07. Маршрут

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Ответственный назначается по услуге, повторная заявка распознаётся, а после сбоя обработка продолжается с остановившегося шага.

#### Scenario: 08. Отчёт

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Пользователь задаёт диапазон дат, сравнивает предыдущий период, просматривает сообщение Telegram и скачивает CSV.

#### Scenario: 09. Поиск источников

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Поиск возвращает выдержки из нескольких документов со ссылками на разделы и объясняет отсутствие ответа.

#### Scenario: 10. Поддержка

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Интерфейс определяет тему и срочность, позволяет редактировать черновик и показывает очередь оператора.

#### Scenario: 11. Контакт и сделка

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Контакт ищется по email, для нового и существующего контактов предусмотрены отдельные результаты. События отражены в журнале.

#### Scenario: 12. Заказы

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Оператор создаёт заказ, назначает ответственного, фильтрует статусы и видит историю изменений.

#### Scenario: 13. Битрикс24

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Демо учитывает воронку и этап в JSON. Можно проверить сценарии успешной сделки, отказа в доступе и превышения лимита.

#### Scenario: 14. GitHub

- **GIVEN** пользователь открыл соответствующую страницу проекта
- **WHEN** он выполняет описанный сценарий
- **THEN** интерфейс показывает результат: Пользователь сравнивает два публичных репозитория, видит даты последних релизов и время обновления данных.
